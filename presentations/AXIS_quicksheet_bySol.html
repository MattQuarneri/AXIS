Agentically eXtensible Instruction Structures

Separate what is defined from what happens at runtime.
Normalize meaning → calculate change → validate state → execute declared work.

A vocabulary for placing responsibilities. Start with AXIS Lite; add structure when it removes ambiguity.

“Static” describes a role: an Effect may be created at runtime and still remain an inert declaration.

02Where the responsibility goes

  1. Normalize at the edge.Adapters produce Intents; raw credentials pass through. The Manager resolves authority.
  2. Keep Actions pure.No IO, mutation, clock, randomness, or global reads. Supply all inputs explicitly.
  3. Give state one owner.The Manager validates Form and Bond invariants, then commits a new Instance.
  4. Describe work before doing it.Effects are data. Only Impact performs network, disk, database, DOM, or queue IO.
  5. Make relationships explicit.Bonds declare rules; Links resolve related state outside Actions. Remote loading uses Impact.
  6. Keep coordination bounded.One Manager per consistency boundary. Cross-boundary work travels through Effects and Intents.

03How change happens

Raw event→Adapter→Intent→Manager→ActionToken + context select the Facet; Links supply related state.

Delta → Manager.commit → new Instance

Validate invariants; adopt state; render its projection.

Effects → Impact → follow-up Intent

Attempt external work; route the outcome through the pure core.

Action(stateSnapshot, intent) → { delta, effects[] }

An Action proposes. A commit changes owned state. Impact changes the outside world. These are separate steps.

04Choose the smallest useful shape

Calculation: Action; add a Form when a contract helps.

Owned state: Form, Instance, Action, Manager; Effect / Impact for IO.

Roles or lifecycle: add Facets; Tokens when scope matters.

Relationships: add Bonds / Links.

Async workflow: explicit outcomes, retries, compensation.

05Keep these distinctions clear

MVC bridge: Model → Form / Instance; Controller → Action / Manager. Facet / Intent describes the View’s meaning; the actual screen is hosted by a Wrapper.
Names: Redux reducer ≈ Action; Redux action ≈ Intent. Token includes revision and workflow handles, not just auth.
Failure: rejection is data; failed IO follows retry / compensation policy. Local commit does not prove remote success.

For your next handoff: name the boundary’s owned state, accepted Intents, emitted Effects, returned outcomes, and policy scope. Map each role to actual paths and symbols. Preserve native names; fourteen roles do not require fourteen files.
